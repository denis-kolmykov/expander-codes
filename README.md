# Система сравнения реализаций экспандерных кодов

[![CI](https://github.com/denis-kolmykov/expander-codes/actions/workflows/ci.yml/badge.svg)](https://github.com/denis-kolmykov/expander-codes/actions/workflows/ci.yml)
[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](LICENSE)
[![Python](https://img.shields.io/badge/Python-3.10%2B-blue.svg)](https://www.python.org/)

Стенд для вероятностного оценивания и сравнения корректирующих кодов:
прогоняет кодовые слова через канал с шумом, декодирует и измеряет качество
с доверительными интервалами. Разрабатывается как основа для последующего
сравнения нейросетевых декодеров на экспандерных кодах.

## Установка и запуск

Требуется Python 3.10 или новее.

```bash
git clone https://github.com/denis-kolmykov/expander-codes.git
cd expander-codes
pip install numpy scipy

python run_comparison.py   # развёртка по уровням шума, результат в results.csv
python tests.py            # 20 проверок корректности, около 10 секунд
```

Зависимости: только NumPy и SciPy. Проверено на Python 3.13, NumPy 2.5.3,
SciPy 1.18.1; в CI прогоняется на Python 3.12.

### Пример использования

Измерить качество одного кода на одном уровне шума:

```python
import numpy as np
from expander_codes import BSC, ExpanderCode, evaluate

code = ExpanderCode.random_regular(n=1008, dv=3, dc=6, seed=2026, flip_mode="max")
result = evaluate(code, BSC(0.02), np.random.default_rng(1))

print(code.name, "скорость", round(code.rate, 3))
print("FER =", result["fer"])
print("интервал", round(result["fer_lo"], 4), "—", round(result["fer_hi"], 4))
```

```
expander_n1008_dv3_dc6_max скорость 0.5
FER = 0.0105
интервал 0.0087 — 0.0127
```

## Как подключить свой код

Система не знает ничего о внутреннем устройстве кода — только об интерфейсе
`Code`. Чтобы подключить новый код (в том числе нейросетевой декодер),
достаточно унаследоваться и реализовать три метода:

```python
from expander_codes import Code

class MyCode(Code):
    @property
    def name(self): ...
    @property
    def n(self): ...          # длина кодового слова
    @property
    def k(self): ...          # число информационных бит

    def encode(self, messages):
        """(B, k) uint8 -> (B, n) uint8"""

    def decode(self, received):
        """(B, n) uint8 -> (X_hat, {'iterations': (B,), 'converged': (B,)})"""

    def params(self):
        """словарь параметров для записи в результаты"""
```

Здесь `B` — размер пакета: все операции выполняются сразу над сотнями блоков,
а не по одному блоку в цикле. Этим и достигается приемлемая скорость на Python.

## Правила декодирования

`ExpanderCode` принимает параметр `flip_mode`:

- `serial` — за итерацию переворачивается один бит с наибольшим числом
  невыполненных проверок (правило Сипсера–Спилмана);
- `max` — переворачиваются все биты с максимальным числом невыполненных
  проверок; на практике лучший вариант из трёх;
- `majority` — переворачиваются все биты, у которых нарушено большинство
  проверок. При степени 3 неустойчиво и включено как предмет сравнения:
  примерно в 5% случаев не справляется даже с одиночной ошибкой.

## Формат результатов

Каждая строка `results.csv` соответствует паре «код + уровень шума» и содержит
35 колонок: параметры кода и графа, параметры канала, зёрна генераторов,
сырые счётчики и производные метрики.

Ключевые метрики:

- `fer`, `fer_lo`, `fer_hi` — доля ошибочных блоков и 95% интервал Уилсона;
- `ber` — доля ошибочных бит;
- `undetected` — доля блоков, где декодер сошёлся к чужому кодовому слову
  (молчаливая порча данных);
- `not_converged` — доля блоков без нулевого синдрома за отведённые итерации
  (обнаружимый отказ);
- `mean_iterations`, `std_iterations` — среднее и СКО числа итераций;
- `girth`, `expansion` — обхват графа и оценка расширения снизу.

Сырые счётчики (`blocks`, `block_errors`, `bit_errors`) сохраняются наряду
с долями, чтобы любую метрику или доверительный интервал можно было
пересчитать без повторного прогона.

## Воспроизводимость

Граф строится от явно заданного зерна (`ExpanderCode.random_regular(seed=...)`),
а каждая точка развёртки получает собственное дочернее зерно, выведенное
из зерна развёртки через `numpy.random.SeedSequence`. Оба зерна попадают
в строку результата (`code_graph_seed`, `sweep_seed`, `point_seed`), поэтому
отдельную точку можно переиграть, не повторяя всю развёртку.

## Известные ограничения

- Все построенные графы имеют обхват 4: случайное построение допускает пары
  битов с двумя общими проверками. Исключение четырёхциклов не реализовано.
- Оценка расширения получается по 500 случайным подмножествам, то есть это
  оценка сверху на худший случай, а не точное значение.
- Поддержан только жёсткий вход (двоичный канал). Мягкий вход (AWGN,
  логарифмические отношения правдоподобия) потребуется для сравнения
  с belief propagation и нейросетевыми декодерами.

## Участие в разработке

Предложения принимаются через issues и pull request'ы.

1. Создайте ветку от `main` с осмысленным именем (`feature/soft-input`,
   `fix/girth-bfs`).
2. Сообщения коммитов — в формате Conventional Commits: `feat:`, `fix:`,
   `docs:`, `refactor:`, `test:`, `ci:`.
3. Перед отправкой прогоните локально то же, что прогоняет CI:

   ```bash
   pip install ruff
   ruff check .
   python tests.py
   ```

4. Новый код сопровождается проверкой в `tests.py`.
5. В описании pull request'а перечислите внесённые изменения и укажите, какие
   проверки добавлены.

### Стиль кода

Стиль задан в `pyproject.toml` и проверяется линтером `ruff`: длина строки
до 100 символов, сортированные импорты, целевая версия Python 3.10.
Имена и комментарии в коде — на русском языке, идентификаторы — на английском.
